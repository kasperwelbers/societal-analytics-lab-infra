    Overview

    The Societal Analytics Lab (VU Amsterdam) runs a small infrastructure for its research: a login service, servers for the tools lab members use, and servers for the research software the lab develops (AmCAT, AnnoTinder). This site describes how that infrastructure is set up and secured, and how our software handles logins. It is written for lab members, for VU IT, and for other research groups with similar needs.

    • The 🔑 is the lab's login service (Keycloak). Everything that needs a login uses it: the lab login on the lab server, and the services on the service VMs.
    • 🌐 Only HTTPS is public. Each server has one reverse proxy (Caddy) in front of its services; the services themselves listen only on the server itself or on internal networks. The database server has no public access at all.
    • Backups: every server backs up /opt every night, encrypted (Backups); for now on the server itself (see Open points).

    Two kinds of servers

    • Physical servers on VU premises: the lab server and the database server. Used for work that needs dedicated hardware or a lot of storage.
    • Virtual machines (VMs) from VU SciCloud, the VU's research cloud (one.labs.vu.nl, see SciCloud). Used for services that are better off on a server of their own: the login service, and some of the lab's services.

    Lab services run on the lab server or on a service VM, whichever suits the service best. An overview of the services: Hosted services.

    IP addresses and the admin hostname of Keycloak are not published here.

    On every server:

    • One reverse proxy (Caddy) with certificates from Let's Encrypt is the only way in. Services listen on 127.0.0.1 or on internal networks.
    • Docker containers bypass a server's firewall, so we follow strict rules for them (Docker warnings).
    • Software versions are pinned and upgraded deliberately; the operating system installs security updates automatically.
    • Secrets are only on the server they are used on, readable only by the account that runs the service.
    • Every app runs with Docker Compose in /opt/<app>, with everything needed to restore it there (settings, files, database dumps). /opt is backed up every night, encrypted, with monitoring; data with a short retention is deleted automatically, and isn't in our backups (Apps on our servers, Backups). VU IT's server backups are the last resort.
